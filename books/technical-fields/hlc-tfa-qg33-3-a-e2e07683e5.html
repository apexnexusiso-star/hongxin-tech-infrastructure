  • 文件定位说明

本文件用于质量管理体系认证中 QG33-3 技术领域包的分组论证、审核员专业能力评价、授权控制、项目匹配、能力扩展和持续保持。本包覆盖计算机咨询活动、计算机设备管理活动以及其他信息技术及计算机服务活动中以系统集成为代表的服务。

本包不采用简单包容口径。计算机咨询、设备管理和系统集成在 QMS 轴下共享 IT 服务需求识别、方案或服务边界、配置资料、交付验证、问题闭环和客户确认基础，但交付物和质量形成路径差异明显。使用时应采用“统一领域包 + 三分支能力标注 + 条件扩展 + 项目边界控制”的口径。

  • 技术领域包构成
小类编码小类名称纳入本包的活动范围主要内部路线特殊边界
33.02.02计算机咨询活动IT 战略规划、信息系统规划、企业架构、技术选型、可行性研究、云迁移规划、数据治理规划、招标技术支持和项目管理咨询。规划咨询、架构设计、选型咨询、云咨询、数据咨询、项目管理咨询。交付物主要是报告、模型、蓝图、路线图和技术文件，不等同于代码实现或现场实施。
33.02.03计算机设备管理活动客户计算机系统、终端、服务器、网络、账号、配置、补丁、备份、事件、变更和服务台的持续管理。桌面外包、服务器运维、网络运维、驻场管理、远程运维中心。核心是持续运行和服务级别，不等同于一次性安装或系统集成项目。
33.02.04其他信息技术及计算机服务活动，特别是系统集成软硬件组合、系统部署、网络联通、接口配置、数据迁移、联调测试、割接上线、验收移交和其他未另分类 IT 服务。基础设施集成、应用系统集成、弱电信息系统集成、云迁移实施、平台升级改造、灾难恢复服务、软件安装服务。核心是项目性交付和系统联通；复杂灾备、关键行业系统和多供应商集成应专项确认。
  • 分组设立的基本逻辑

本包的共同对象是客户信息技术服务成果。QMS 关注的共同机理不是具体代码或硬件制造，而是客户需求如何被识别、转换为方案或服务边界，相关配置、资源、接口和过程如何受控，最终成果如何通过客户确认、运行验证、服务报告或验收移交形成可证明的服务质量。

共同质量形成链可以概括为：客户需求和服务范围 → 现状或资源识别 → 方案、服务目录或实施计划 → 配置、资源、接口和人员安排 → 服务交付或项目实施 → 验证、报告、验收或关闭 → 问题、变更和客户反馈闭环。

咨询活动偏向决策支持和方案成果；设备管理偏向持续运行和服务级别；系统集成偏向项目实施、联通和验收。三者差异较大，但均属于 IT 服务质量形成链，且在需求识别、配置资料、客户沟通、问题闭环和服务证据方面具有共同能力基础，因此可以设为一个 QMS 技术领域包，并通过分支标注控制能力边界。

  • 专业小类关系类型与授权后果
关系类型含义授权后果典型控制方式
共同基础关系共享信息技术服务、需求识别、版本或配置控制、验证放行和反馈闭环等基础能力。可简化基础专业面谈，但仍应确认目标小类或目标路线的实际经历。资料评审、案例判断、专业面谈。
并列分支关系同属本技术领域包，但交付对象、过程重点或质量形成路径存在分支差异。应记录实际分支能力，不把同包经历理解为全分支能力。分支标注、限定使用、项目技术支持。
条件扩展关系已具备相邻分支能力，具备扩展基础，但目标路线仍有专门知识和证据要求。完成补充培训、案例评审、专业面谈或见证审核后方可扩展。培训考核、案例评审、见证审核。
专项确认关系涉及特殊平台、强内容属性、高可用服务、大规模数据或复杂集成边界。在项目使用前应进行专项确认，必要时配置技术专家支持。专项面谈、技术专家评审、项目前确认。
不可直接替代关系相关 IT 经历不足以证明目标小类的质量形成链能力。不得作为目标能力的单独授权依据。重新评价、补充经历或限定项目类型。
边界受控关系互联网服务、数据、内容、账号、版权、许可或客户行业要求改变使用边界。授权记录应写明边界，项目匹配时按实际服务内容确认。授权备注、合规类别清单、技术支持。
咨询、设备管理、系统集成三分支共享 IT 服务需求、方案、配置、交付和客户确认基础。可共享 IT 服务基础评价，但必须记录实际分支能力。分支标注、案例面谈、项目类型限定。
咨询到系统集成咨询成果可作为实施输入，但咨询不等于实施。仅有咨询经历不得作为复杂集成项目能力证明。补充实施计划、联调、验收和转维案例。
设备管理到系统集成运维人员熟悉配置和运行，但项目集成交付另有方法。仅有运维经历扩展集成时应确认项目实施和验收能力。集成项目案例、现场联调和割接记录评审。
系统集成到设备管理集成人员熟悉部署和联通，但持续运行服务另有机制。仅有集成经历扩展运维时应确认服务台、事件、变更、备份和服务报告能力。服务周期案例和 SLA 证据追溯。
  • 本体系共同能力基础
共同能力维度本包共同基础可共享的审核判断不能共享的边界
客户要求和范围界定均需识别客户业务问题、IT 服务对象、范围、排除项、角色和交付边界。能判断服务或项目范围是否清楚，相关方需求是否转化为交付要求。咨询目标、运维服务级别、集成项目验收准则不能相互替代。
配置和资料控制均需管理系统清单、资产、接口、账号、拓扑、方案、计划和版本资料。能判断配置资料是否支撑服务实施、变更和追溯。CMDB、架构蓝图、现场拓扑和迁移脚本的专业深度不同。
服务或项目实现均需按计划组织人员、工具、资源、供应商和客户接口。能判断服务过程是否按计划实施并形成证据。咨询成果、长期运维和一次性交付的过程证据不同。
验证和客户确认均需通过评审、报告、验收、服务报告或运行验证证明交付结果。能判断客户确认、验证结果和遗留问题是否闭环。系统联调、恢复演练、服务级别统计和咨询成果评审不能简单互认。
问题、变更和改进均面临客户需求变化、配置变更、问题单、遗留事项和改进闭环。能沿一个问题或变更追溯原因、处理、验证和客户沟通。高可用系统、灾备、复杂网络和多供应商责任边界需专项确认。
  • 本体系核心控制要求

本章所称关键质量特性，是指服务或软件交付结果中影响顾客可接受性的功能、性能、可用性、完整性、可追溯性、服务响应和交付一致性等特性。

QMS 审核应首先确认客户需求、服务目录、项目范围、交付物、排除项、验收准则和责任矩阵是否明确。其次应确认信息技术服务过程中的资料控制，包括系统清单、拓扑、接口、账号、配置、方案、计划、问题清单、变更记录和服务报告。第三，应确认服务或项目实施过程是否按计划执行，人员能力、工具、供应商、现场条件和客户窗口是否受控。第四，应确认验证和放行证据是否充分，包括咨询成果评审、服务级别报告、联调测试、迁移比对、恢复演练、客户验收和遗留问题关闭。第五，应确认客户反馈、事件、问题、变更和改进是否闭环。

对咨询活动，应关注资料来源、现状模型、方案比较、路线图和成果版本一致性。对设备管理，应关注资产准确性、监控告警、服务台闭环、补丁、备份、变更和服务报告。对系统集成，应关注设计到实施的转换、设备和软件配置、接口联调、数据迁移、割接回退、验收移交和转维资料。

  • 分小类或内部路线差异分析
小类/路线与本包共同基础主要差异差异对能力授权的影响控制方式
33.02.02 计算机咨询共享客户需求、资料控制、方案形成和客户确认基础。交付物为报告、模型、蓝图、路线图和技术文件。应标注咨询分支；不替代实施和运维能力。咨询成果案例、访谈资料和方案比较矩阵评审。
33.02.03 计算机设备管理共享服务范围、配置资料、问题闭环和客户报告基础。持续运行、事件、变更、补丁、备份、服务台和 SLA 突出。应标注设备管理或运维分支；不替代系统集成项目能力。服务周期、工单、CMDB 和服务报告追溯。
33.02.04 系统集成及其他 IT 服务共享客户需求、配置、计划、验证和客户确认基础。项目实施、软硬件部署、接口联调、迁移、割接和验收突出。应标注系统集成分支；复杂集成和灾备需专项确认。项目案例、联调记录、迁移比对和验收移交评审。
IT 战略或架构咨询共享咨询过程和资料控制基础。抽象层级高，结果多为决策文件。仅能证明咨询能力，不能证明实施能力。访谈、模型、路线图和成果评审。
桌面或服务器运维共享设备管理基础。现场响应、终端或服务器配置、补丁和备份突出。应区分桌面、服务器、网络等路线。资产台账、工单和恢复记录抽样。
网络或弱电系统集成共享系统集成基础。现场施工、网络拓扑、设备配置和多方联调突出。应确认现场实施和网络配置能力。拓扑、配置、连通性和现场验收记录。
灾难恢复服务共享运维和集成基础。恢复目标、副本、演练、切换和回切突出。属于专项确认路线。灾备方案、演练记录和恢复验证追溯。
软件安装服务共享实施和客户确认基础。安装、配置、权限、版本和客户环境突出。简单安装可归一般集成；复杂应用部署需确认。安装计划、配置清单、验证和移交资料。
  • 分组合理性论证结论

本组可以设立的理由在于三类活动均属于信息技术服务质量形成链，均需要识别客户要求、定义服务或项目边界、控制配置资料、实施服务或项目过程、验证交付结果并处理客户反馈。QMS 审核的基本判断路径可以共享。

本组不能作为三类能力的无差别互认。咨询、设备管理和系统集成的交付对象、过程证据和质量验证方式差异明显。机构应采用“统一领域包 + 分支能力标注 + 条件扩展 + 专项边界控制”的使用口径。

  • 审核关键要点与抽样方法
抽样场景现场必看记录必查纵向追溯路径追问方向
一个咨询项目访谈资料、模型图、方案报告、成果评审记录。合同范围、资料清单、访谈纪要、比较矩阵、路线图、客户确认。客户问题 → 调研 → 现状模型 → 方案比较 → 成果交付 → 客户确认。资料来源是否充分；结论如何从证据形成。
一个设备管理服务周期服务台、监控平台、CMDB、备份系统。服务目录、工单、告警、变更、补丁、备份、服务报告。服务范围 → 资产配置 → 监控事件 → 工单处理 → 验证关闭 → 周期报告。服务级别如何统计；重复事件如何处理。
一个系统集成项目现场拓扑、设备软件清单、联调环境、项目问题清单。实施计划、配置记录、联调测试、迁移比对、割接记录、验收移交。客户需求 → 方案设计 → 实施配置 → 联调 → 割接 → 验收 → 转维。设计如何转换为现场配置；遗留问题如何关闭。
一次灾难恢复演练灾备平台、恢复环境、监控和演练现场。恢复目标、演练计划、恢复记录、差异项、改进措施。恢复需求 → 副本准备 → 演练执行 → 验证 → 问题关闭。恢复结果是否满足目标；回切条件是否明确。
一个变更或故障服务台、配置项、日志和客户沟通记录。变更申请、影响分析、实施记录、回退、关闭确认。问题或变更 → 影响分析 → 实施 → 验证 → 客户确认。影响范围如何识别；是否更新配置资料。
  • 能力扩展与条件授权
起点能力目标能力可扩展依据必须补充确认授权限制
计算机咨询系统集成具备需求识别、方案设计和客户沟通基础。现场实施、配置、接口联调、迁移、割接和验收案例。未确认前不得用于复杂集成项目。
系统集成计算机咨询具备项目方案、客户需求和技术结构背景。咨询方法、访谈、现状建模、方案比较和路线图案例。未确认前限用于实施相关咨询。
设备管理系统集成熟悉客户环境、配置和运行问题。项目计划、部署、联调、验收和转维资料。需按项目复杂度限定。
系统集成设备管理熟悉系统部署和配置关系。服务台、事件、问题、变更、补丁、备份和服务报告案例。未确认前不得用于长期运维服务。
一般设备管理灾难恢复服务具备备份和运行基础。恢复目标、演练、切换、回切和副本验证案例。灾备项目应专项确认。
软件安装服务复杂应用系统集成具备安装配置基础。多系统接口、数据迁移、联调和客户验收案例。未确认前限简单安装项目。
  • 培训、考核与作业指导书需求

本组应建立 IT 服务 QMS 专业培训，内容包括客户需求识别、服务目录、项目范围、配置资料、变更和问题闭环、客户确认、服务报告和验收移交。咨询分支应增加访谈、现状建模、方案比较和成果版本控制。设备管理分支应增加 CMDB、服务台、监控、事件、问题、变更、补丁、备份和服务级别统计。系统集成分支应增加实施计划、现场配置、接口联调、数据迁移、割接回退、验收和转维。

考核应要求审核员分别完成咨询项目、运维服务周期和系统集成项目的质量形成链追溯。作业指导书应提供三类分支的抽样路径和能力扩展判定表。

  • 常见合规义务类别与标准适用提示

本组可能涉及互联网信息服务、网络安全、数据安全、个人信息保护、电子认证、密码应用、增值电信业务、政府采购、招投标、客户行业信息系统建设和运行规则、商业秘密、合同交付和知识产权等类别。文件不列具体标准编号和年份；适用性应使用机构受控的现行有效清单、客户合同、行业资料和项目实际服务范围确认。

合规义务类别用于识别外部要求如何进入咨询方案、服务目录、配置要求、验证要求和客户交付资料，不替代行政许可、政府监管、客户专门验收或第三方技术测评。

  • 分组使用限制和法定边界

本分组仅用于 QMS 认证中的技术领域包论证和审核员专业能力控制。管理体系审核不替代信息系统建设许可、网络安全等级保护测评、密码应用安全性评估、数据安全或个人信息法定评估、特种行业系统验收、行政执法、政府采购评审或客户专项测试验收。

当项目涉及关键行业系统、重大数据迁移、复杂云迁移、灾难恢复、高可用系统、多供应商集成、大规模运维外包或涉密相关系统时，应在项目匹配阶段追加专项确认或技术专家支持。

  • 分组结论与使用口径

QG33-3 可作为质量管理体系计算机咨询、设备管理及系统集成技术领域包使用。授权时应记录审核员在咨询、设备管理、系统集成、灾难恢复、软件安装、网络集成等分支上的实际能力。组内扩展应通过培训、案例评审、专业面谈、见证审核或技术支持控制。

文件维护触发条件包括：IT 服务模式、云迁移和运维模式、数据安全和个人信息处理要求、系统集成技术、灾备服务和客户行业规则发生实质变化，或上层分组使用中出现能力匹配争议。
