33.01.01 电脑游戏发行 专业小类基础卡

A. 标识与定位

A1 小类名称、分类代码、在分类体系中的位置

字段内容
专业小类代码33.01.01
专业小类名称电脑游戏发行
所属大类33 软件、信息技术、数据处理和互联网门户相关服务
所属中类33.01 软件发行
本卡定位描述电脑游戏从作品权利、版本包、渠道、上线资料、更新补丁、用户服务到运营接口的发行活动事实，侧重游戏内容资产、版本发布、渠道分发、版权授权和在线服务边界。
与上层文件关系本卡只记录底层行业事实、技术边界、过程、设施、投入、检测计量手段和维护信息，不记录任何上层体系判断。

A2 定义与范围界定

本小类是指围绕电脑游戏作品的商业发行、渠道分发、版本上线、授权交付、补丁更新、下载或客户端分发、用户账号接入和配套服务资料形成的活动。

本小类通常包括电脑客户端游戏、联网电脑游戏、单机电脑游戏数字发行、游戏平台上架、发行代理、版本包管理、补丁和资料片发布、语言本地化、发行渠道协调、数字授权和用户支持接口。

本小类不以源代码定制开发为主，不以一般软件产品发行、计算机编程、系统集成、门户网站内容组织或数据托管为主。

A3 边界说明：相邻小类区分点与排除项

易混淆活动混淆原因区分依据本卡处理原则
33.01.02 其他软件发行二者都涉及软件版本和渠道本小类以游戏作品、游戏内容资产、玩家账号和游戏发行渠道为主非游戏软件产品发行归其他软件发行。
33.02.01 计算机编程活动游戏发行方可能组织补丁和工具开发编程以源代码开发和定制交付为主，发行以作品上线和渠道交付为主主导活动为代码开发时归编程活动。
33.03.02 门户网站游戏发行可能使用官网和社区门户门户网站以信息入口、内容组织和流量聚合为主，游戏发行以游戏作品交付为主官网社区仅作为发行渠道接口时归本小类。
33.03.01 数据处理、托管及相关活动网络游戏运行可能依赖服务器托管托管以算力、存储和运行环境为交付对象，发行以游戏作品和版本为交付对象独立服务器托管归数据处理托管。
文化娱乐或广告活动游戏宣传、推广和赛事活动与发行相邻宣传活动以营销传播为主，不改变游戏软件发行对象营销传播不是本卡主导范围。

明确排除项包括：游戏源代码受托开发、游戏美术外包、独立云服务器托管、一般门户运营、单纯广告推广、线下娱乐活动和硬件游戏设备制造。

A4 分组特征摘要

受控维度本小类特征摘要
主导活动类型数字内容软件发行和渠道交付服务。
交付对象游戏版本包、启动器、补丁、DLC、授权密钥、渠道上线资料、用户服务接口和运营配置。
核心过程性质作品权利确认、版本冻结、内容资源打包、渠道适配、上线发布、补丁分发、账号计费接口和运行反馈闭环。
主要技术基础游戏引擎构建物、资源包、补丁系统、DRM/授权、启动器、反作弊组件、渠道 SDK、日志埋点和玩家账号体系。
产业链段位位于游戏开发完成后、玩家获取和在线运行之前的发行与渠道连接环节。
典型规模跨度从小型独立游戏发行商到大型游戏平台和跨区域代理发行组织。
主要分型轴按单机/联网、买断/订阅/道具、客户端/云游戏、国内/引进、本地化深度和渠道模式分型。
分组比较提示与其他软件发行共享版本和许可管理，但游戏发行特有版号、内容资产、补丁、玩家账号、反作弊和渠道 SDK 链条。

术语解释

版本包可安装或可下载的游戏交付包，通常包含程序、资源、配置和校验信息。
补丁用于修复缺陷、调整平衡、增加内容或更新客户端的增量包或全量包。
资料片/DLC在原游戏基础上扩展的内容包、关卡、角色、剧情或功能模块。
启动器用于登录、更新、校验、启动和渠道联动的客户端入口程序。

B3 关键技术概念说明

游戏发行的核心不是单纯上传安装包，而是把一个可玩的软件作品转化为可被目标用户获取、安装、登录、更新和持续使用的发行单元。 游戏版本具有内容资产和软件系统双重属性。程序、资源、剧情、角色、音频、美术、脚本、配置、补丁和服务器协议之间需要一致，否则会出现客户端版本、服务器版本和渠道资料不匹配。 发行活动通常连接版权、内容、渠道、支付、用户账号、社区反馈和更新运营，边界识别应围绕作品交付和渠道上线，而不是围绕是否有程序员参与。

C. 产品或服务描述

C1 典型产品或服务的类别与用途

类别典型对象主要用途
电脑客户端游戏发行PC 客户端游戏、联网客户端、启动器和补丁包向玩家提供下载、安装、登录和持续更新入口。
单机游戏数字发行安装包、激活码、平台上架包、离线补丁通过数字商店或官网交付游戏作品。
代理发行服务授权代理、本地化、渠道接入、上线资料和运营接口帮助开发商进入目标市场或平台。
游戏更新服务补丁、资料片、赛季内容、热更新资源维持版本可用性和内容迭代。

C2 主要功能、性能维度

本小类的客观功能维度包括版本完整性、安装成功率、补丁兼容性、渠道适配、账号登录可用性、支付接口可用性、授权验证稳定性、下载速度、更新回滚能力、内容资源一致性、用户服务响应和运行日志可追溯性。不同游戏类型还会关注延迟、服务器容量、匹配服务、反作弊识别、跨区域语言配置和客户端环境兼容性。

C3 常见产品/服务分型

分型维度常见类型技术差异提示
联网方式单机、局域网、在线多人、云游戏服务器依赖和账号接口差异明显。
商业模式买断、订阅、内购、道具、广告支持支付、授权和用户权益配置不同。
渠道模式官网、游戏平台、应用商店、代理渠道上架资料、SDK、结算和版本审查节奏不同。
内容更新静态版本、补丁迭代、赛季制、资料片制版本包和内容资源链条不同。
市场范围国内发行、海外发行、引进代理、本地化发行语言、版权、支付和内容资料差异较大。

C4 典型服务族专业差异补充

服务族结构与过程特征底层识别提示
大型联网游戏客户端、服务器、账号、支付、匹配、反作弊和运营配置强耦合不能只看安装包，应识别客户端和服务器协议链。
独立单机游戏版本包、授权、存档、成就和平台上架更突出发行边界通常比运营边界轻。
云游戏发行客户端较轻，云端渲染、串流和账号调度更突出应识别算力托管和游戏发行的边界。
引进代理游戏版权授权、本地化、渠道上架和地区配置突出应识别开发方、发行方和平台责任边界。
电子竞技相关游戏赛事版本、观战、反作弊和延迟配置更敏感赛事运营本身不是本小类主导活动。

D. 过程与技术

D1 主要工艺/过程流程

`mermaid flowchart LR A["游戏作品和授权输入"] B["版本冻结与构建接收"] C["内容资源和本地化处理"] D["渠道 SDK 与配置适配"] E["测试服或灰度发布"] F["正式上线与补丁分发"] G["运行反馈和版本维护"] A --> B B --> C C --> D D --> E E --> F F --> G `

游戏发行流程通常从作品权利和版本输入开始。发行方接收开发方提供的构建物、资源包、说明文档、授权资料和配置要求，先确认游戏作品、版本号、平台、区域、语言、渠道和交付方式。 发行中段围绕版本包形成和渠道适配展开。安装包、启动器、补丁、服务器接口、渠道 SDK、支付接口、账号接口、内容资源和上线资料需要形成一致的发布组合。 上线后，发行活动继续围绕补丁分发、用户反馈、渠道资料更新、版本回滚、异常公告和客服知识库维护展开。该后续活动属于发行链条的组成部分，但若主体转向服务器托管或游戏开发，应按实际主导活动识别。

D5 常见过程路线或服务路线差异

路线典型组织形态差异说明
自研自发开发商兼发行方开发和发行协同强，版本决策链短。
代理发行发行商代理开发商作品授权、本地化、渠道关系和结算边界更突出。
平台发行通过大型游戏平台或应用商店上架平台规则、SDK、版本审查和渠道后台配置更突出。
全球发行跨区域多语言和多渠道发行本地化、区域服、支付和内容差异更大。
持续运营型发行长期在线游戏或赛季制游戏补丁、活动配置、服务器协议和用户服务频率高。

D6 典型路线识别提示

识别对象典型信息技术含义
版本号和包体客户端版本、资源版本、补丁号、渠道号识别发行对象和发布批次。
渠道后台上架状态、地区、价格、SDK、公告和包体记录识别发行渠道和配置范围。
服务器协议客户端最低版本、登录协议、资源清单识别客户端和运行服务接口。
授权资料发行区域、平台、期限、语言、商标和内容授权识别权利边界。
用户服务资料客服 FAQ、封禁规则、支付处理、补丁公告识别发行后服务边界。

D7 游戏发行的版本包、渠道和运行接口链条补充

游戏发行最容易被误写成一般软件发行。实际识别时，应把“版本包 - 渠道 - 账号 - 支付 - 补丁 - 用户服务”作为一条链来看。版本包只是起点；渠道 SDK 决定登录和支付入口，启动器决定更新方式，补丁服务器决定版本切换，反作弊和日志决定运行反馈，客服知识库决定玩家问题如何回到版本维护。若企业只做官网宣传或社区运营而不控制游戏包、授权和渠道上线，不宜归入本小类；若企业控制服务器托管但不控制游戏发行权和上线资料，则应转向数据处理或托管活动识别。

E. 产业链与边界

E1 上游供应

上游包括游戏开发商、游戏引擎和工具供应商、美术音频外包方、本地化供应商、支付和账号平台、版权方、游戏平台、CDN和云资源供应方。

E2 下游应用/客户

下游包括玩家、游戏平台、代理渠道、网吧和电竞场景、海外渠道、客服服务商、社区运营团队和数据分析团队。

E3 本小类在产业链中的位置

本小类位于游戏开发完成之后、用户获取和在线运行之前的发行转换环节。它把游戏作品和技术构建物转化为可上线、可下载、可更新、可授权和可支持的商业发行单元。

E4 常见委外/外包环节

委外/外包环节行业常见原因边界提示
本地化多语言和地区文化适配需要专业资源本地化不改变发行主体。
渠道接入测试不同平台 SDK 和审查规则差异大接口适配可外包，但版本责任需识别。
CDN和下载加速高并发下载需要外部节点资源分发资源不等同于发行权。
客服和社区支持用户规模大时常由服务商承接用户服务边界应与发行规则一致。
反作弊或数据分析专业算法和运行数据服务常外包外部服务输出只是发行运行支持。

H. 行业本底特征

H1 技术复杂度、自动化与人工依赖程度

电脑游戏发行技术复杂度受游戏类型、联网程度、渠道数量、用户规模和更新频率影响。自动化主要体现在构建分发、补丁制作、渠道包生成、日志采集和数据统计；人工依赖主要体现在权利确认、本地化、上线资料、内容资源判断、渠道协调和用户服务。

H2 典型组织形态

组织形态典型特征常见资源配置
独立发行团队人员少，依赖外部平台和云资源版本管理、渠道后台、客服和社区工具。
大型游戏发行商多项目、多渠道、多区域并行制品库、发行平台、数据分析、客服中心和合规资料库。
开发发行一体公司开发和发行在同一组织内代码仓库、构建系统、发行后台和运营配置。
代理发行组织掌握地区渠道和本地化能力授权资料、渠道资源、本地化和用户服务团队。
平台型发行组织同时经营数字商店或启动器平台后台、支付账号、推荐系统和下载分发资源。

H3 客观存在的易出问题环节/技术敏感点

敏感点客观影响链
权利边界不清授权范围不明确 → 渠道或地区使用超出约定 → 作品交付责任和版权责任界面混乱
版本包错配客户端、资源包和服务器协议不一致 → 用户无法登录或功能异常 → 补丁和客服压力上升
渠道 SDK 版本混乱不同渠道接口配置不一致 → 登录支付回调异常 → 用户权益记录不一致
补丁依赖缺失差分包依赖旧版本 → 跳版本用户更新失败 → 回滚和重新下载成本增加
本地化遗漏语言包、字体或文化元素未适配 → 界面显示异常或内容理解偏差 → 用户反馈集中
反作弊误判检测规则和客户端版本不匹配 → 正常用户被限制或异常行为漏识别 → 用户服务争议增加
下载节点不足首发流量超过分发容量 → 下载失败或速度过慢 → 上线体验波动
客服知识库滞后版本更新后问题说明未同步 → 工单处理口径不一致 → 用户问题重复积累

H3 只记录行业中客观存在的敏感点及事实因果链，不对其在任何上层视图中的重要性作判断。
