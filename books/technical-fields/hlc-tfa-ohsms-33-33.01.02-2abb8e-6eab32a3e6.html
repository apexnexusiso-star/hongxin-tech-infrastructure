33.01.02 其他软件发行 专业小类基础卡

A. 标识与定位

A1 小类名称、分类代码、在分类体系中的位置

字段内容
专业小类代码33.01.02
专业小类名称其他软件发行
所属大类33 软件、信息技术、数据处理和互联网门户相关服务
所属中类33.01 软件发行
本卡定位描述非游戏标准软件产品的版本产品化、许可授权、安装包、渠道、更新、文档和用户支持事实，侧重发行与定制开发、咨询和托管服务的边界。
与上层文件关系本卡只记录底层行业事实、技术边界、过程、设施、投入、检测计量手段和维护信息，不记录任何上层体系判断。

A2 定义与范围界定

本小类是指除电脑游戏以外的软件产品发行活动，包括标准化软件产品的打包、许可、渠道分发、安装介质或下载包发布、更新维护、授权管理和随附资料交付。

本小类通常包括办公软件、工具软件、开发工具、行业通用软件、系统工具、中间件组件、插件、桌面应用、移动应用非游戏类发行和标准软件订阅交付。

本小类不包括受托编程开发、客户现场系统集成、计算机咨询、设备管理、数据托管、门户网站运营和电脑游戏发行。

A3 边界说明：相邻小类区分点与排除项

易混淆活动混淆原因区分依据本卡处理原则
33.01.01 电脑游戏发行都可能涉及软件上架和用户获取游戏发行以游戏作品、玩家账号、补丁和渠道 SDK 为主非游戏服务按自身主导活动识别。
33.02.01 计算机编程活动都可能产生或修改软件编程以受托开发、代码实现和定制交付为主主导输出为代码或定制系统时归编程。
33.02.02 计算机咨询活动都可能提供方案和技术文档咨询以诊断、规划、方案和选型意见为主不直接承担实现或运行时归咨询。
33.02.03 计算机设备管理活动都可能涉及运行维护设备管理以客户计算环境运行和运维为主长期运行托管按设备管理或数据托管识别。
33.02.04 其他信息技术及计算机服务活动系统集成与开发、咨询、运维相邻系统集成以多系统、多设备、多软件互联实施为主按交付对象和责任边界识别。
33.03.01 数据处理、托管及相关活动都可能使用云、服务器和数据数据处理托管以算力、存储、数据作业和托管环境为主独立托管或数据加工归数据处理托管。
33.03.02 门户网站都可能以网站或平台提供服务门户网站以内容入口、检索、聚合、推荐和流量组织为主按内容组织和入口属性识别。

明确排除项包括：电脑游戏发行、客户定制开发、系统集成实施、独立咨询报告、数据中心托管、门户内容运营和硬件设备制造。

A4 分组特征摘要

受控维度本小类特征摘要
主导活动类型标准化软件产品发行和授权交付。
交付对象安装包、镜像、许可密钥、订阅权益、发行说明、用户文档、补丁和升级包。
核心过程性质产品版本冻结、打包签名、许可模型配置、渠道发布、更新分发、文档维护和用户支持。
主要技术基础版本管理、安装器、代码签名、许可证服务器、自动更新、包管理、兼容性矩阵和发行说明。
产业链段位位于软件研发完成后、用户部署和使用之前的产品化交付环节。
典型规模跨度从单一桌面软件发行者到多产品线独立软件厂商和云订阅软件供应商。
主要分型轴按桌面/服务器/移动/云订阅、永久许可/订阅许可、闭源/开源商业发行、行业通用/工具软件分型。
分组比较提示与编程活动的边界在于交付对象是否为标准产品版本；与游戏发行的边界在于是否以游戏内容资产和玩家运行服务为主。

B3 关键技术概念说明

软件发行的本质是把研发产物转化为可识别、可安装、可授权、可更新和可支持的标准化产品版本。 许可模型是软件发行的重要边界。永久许可、订阅许可、模块许可、并发许可、设备许可和账号许可会改变交付资料、授权系统和客户使用方式。 软件发行与编程开发的区别不在于是否有代码，而在于主导活动是否围绕标准产品版本、渠道和许可交付。

C. 产品或服务描述

C1 典型产品或服务的类别与用途

类别典型对象主要用途
桌面软件办公、图形、工具、安全、开发辅助软件供个人或组织终端安装使用。
服务器软件数据库、中间件、服务端组件、管理平台供组织部署在服务器环境中运行。
移动应用软件非游戏类应用、工具、办公和生活服务应用通过应用商店或企业渠道分发。
云订阅软件在线软件产品、账号授权、SaaS 服务通过订阅方式提供标准功能。

C2 主要功能、性能维度

本小类的客观功能维度包括安装成功率、版本完整性、许可可用性、兼容性、升级路径、补丁可用性、文档完整性、用户支持响应、依赖管理、数据迁移工具可用性、接口兼容、可配置性和生命周期支持期限。

C3 常见产品/服务分型

分型维度常见类型技术差异提示
部署形态本地安装、私有部署、公有云订阅、混合交付安装、许可和升级方式不同。
许可模式永久许可、订阅许可、模块授权、并发授权、开源商业发行权益控制和交付资料不同。
产品类别基础软件、工具软件、行业通用软件、中间件、开发工具技术依赖和用户环境差异大。
发布节奏快速迭代、长期支持、维护补丁、主版本升级版本和兼容性管理差异明显。
渠道官网、应用商店、经销商、企业批量授权、云市场上架资料和客户支持接口不同。

C4 典型服务族专业差异补充

服务族结构与过程特征底层识别提示
桌面工具软件终端环境复杂，安装和兼容性突出关注安装器、驱动、插件和卸载残留。
服务器软件依赖操作系统、数据库、中间件和网络端口关注部署拓扑、配置和升级路径。
开发工具插件、编译器、SDK、项目模板和依赖管理突出关注版本兼容和开发者文档。
云订阅软件账号、租户、套餐、权限和在线更新突出关注订阅权益和服务配置。
开源商业发行开源组件、许可证、二次打包和企业支持突出关注组件清单和授权边界。

D. 过程与技术

D1 主要工艺/过程流程

`mermaid flowchart LR A["产品版本冻结"] B["安装包和制品打包"] C["签名与完整性校验"] D["许可和订阅配置"] E["渠道发布"] F["更新和补丁分发"] G["用户支持和生命周期维护"] A --> B B --> C C --> D D --> E E --> F F --> G `

其他软件发行通常始于研发团队形成可发布版本。发行团队对版本号、分支、构建物、依赖、说明文档和已知问题进行整理，形成面向用户的发行候选包。 中段过程围绕产品化和授权展开。安装包、容器镜像、插件包、许可证、订阅权益、发行说明、用户手册和升级指南需要一致，避免用户获得无法安装或无法授权的版本。 发布后，发行活动继续围绕补丁、漏洞修复、兼容性更新、生命周期公告、客户问题和渠道资料维护展开。若活动转为按客户需求开发功能，应转入编程活动识别。

D2 关键过程、特殊过程

过程环节主要输入主要输出技术控制点
版本冻结代码分支、制品、缺陷清单、发布计划发行候选版本分支、版本号、变更范围和发布日期一致。
制品打包程序、依赖、脚本、镜像、配置模板安装包或镜像依赖完整、安装路径、卸载、升级和回滚规则。
签名和校验证书、哈希、签名工具签名制品和校验信息来源标识、完整性和证书有效边界。
许可配置许可证策略、套餐、模块、账号或设备规则可用授权模型期限、并发、模块和离线授权规则。
文档同步发行说明、安装手册、用户手册、接口说明随附资料包版本、功能、已知问题和兼容性一致。
渠道发布官网、商店、云市场、经销商资料上架软件和产品资料包体、价格、区域、版本和支持入口一致。
更新维护补丁、升级包、生命周期计划更新发布和维护公告升级路径、兼容性、回滚和终止支持。
用户支持工单、FAQ、知识库、授权问题记录支持资料和问题闭环授权、安装、升级和缺陷问题分类。

D2 关注的是过程本身需要控制的技术对象；H3 关注行业中客观上容易出现问题的环节及其事实因果链，二者不互相替代。

渠道系统官网后台、应用商店后台、云市场后台、经销商门户管理软件上架和下载。
文档系统知识库、文档站、版本说明工具维护用户资料和发布说明。

D4 主要原辅材料与投入

投入类别常见投入技术特征
软件制品程序、镜像、插件、脚本、依赖库形成软件产品交付包。
版本资料版本号、变更清单、缺陷状态、兼容性矩阵支撑发布和维护。
授权资料许可条款、价格、套餐、密钥或账号规则形成用户使用边界。
文档资料安装、配置、用户、接口和升级文档支撑用户部署和使用。

反馈资料崩溃日志、工单、客户问题、使用统计支撑补丁和生命周期维护。

D5 常见过程路线或服务路线差异

路线典型组织形态差异说明
传统软件发行安装包或光盘介质为主安装、授权和升级包更突出。
应用商店发行通过平台上架和审查平台规则、签名和分发资料更突出。
企业批量授权面向组织客户许可证、部署包和支持资料更突出。
云订阅软件发行通过在线账号交付租户、套餐、权限和持续更新更突出。
开源商业发行基于开源项目形成商业版本许可证、组件清单和支持服务边界更突出。

D6 典型路线识别提示

识别对象典型信息技术含义

许可证配置授权方式、期限、模块、账号识别使用权益边界。
安装包结构依赖、脚本、签名、清单识别产品化程度。
渠道页面产品名称、版本、价格、支持入口识别分发渠道。
生命周期公告支持期限、维护状态、替代版本识别维护边界。

D7 标准软件发行与定制开发边界补充

其他软件发行最容易与计算机编程活动混淆。识别关键在于输出是否为可复用的标准产品版本。若组织围绕同一软件产品反复形成安装包、许可、发行说明、补丁和用户支持，即使内部存在研发活动，主导活动仍可表现为软件发行；若组织根据单个客户需求编写专用功能、接口或业务系统，交付对象是客户专属代码和系统，则应转向编程活动识别。云订阅软件也不因没有安装包而脱离发行属性，关键在于是否提供标准化软件产品权益。

E. 产业链与边界

E1 上游供应

上游包括软件研发团队、开源组件社区、第三方库供应商、证书服务、应用商店、云市场、经销渠道和文档翻译服务。

E2 下游应用/客户

下游包括个人用户、企业客户、渠道商、云市场、集成商、培训服务商和软件运维支持团队。

E3 本小类在产业链中的位置

本小类位于软件研发成果和用户部署使用之间，把软件制品转换为可安装、可授权、可升级和可支持的软件产品。

E4 常见委外/外包环节

委外/外包环节行业常见原因边界提示
安装包制作专业打包工具和平台差异复杂外包不改变软件发行责任边界。
文档翻译多语言市场需要本地文档翻译不等同于软件发行主体。
渠道上架代理渠道规则和区域资源差异大上架代理需与发行权区分。
客户支持软件用户规模大时外包一线支持支持口径应与版本资料一致。
安全扫描或组件分析第三方工具识别依赖和漏洞扫描输出是发行资料输入。

E5 典型接口资料与数据流转补充

接口环节常见资料或数据识别价值
研发接口制品、变更清单、缺陷状态识别可发布版本。
渠道接口包体、价格、说明、截图、支持入口识别分发状态。
许可接口密钥、账号、订阅、模块规则识别使用权益。
客户接口安装日志、工单、兼容性问题识别支持和补丁输入。
组件接口开源依赖、第三方库、插件识别软件组成边界。

F. 适用法规与技术标准

F1 行业准入/资质/许可要求

本小类通常涉及软件著作权、著作权许可、互联网信息服务、应用商店上架、电子合同、电子商务、加密功能、特定行业软件准入或客户行业规则等类别。本卡仅保留类别指针。

F2 强制性产品标准、主要国家/行业技术标准

标准类别可能覆盖内容本卡处理方式
软件工程与软件生命周期标准类别需求、设计、编码、测试、配置、发布、维护、文档和项目过程作为软件过程事实和术语来源类别记录，具体编号由受控清单核验。
信息安全与网络安全技术标准类别身份鉴别、访问控制、加密、日志、漏洞、备份、连续性和安全配置仅作为信息技术事实来源类别，具体适用性由项目资料确认。
数据管理与数据服务标准类别数据模型、元数据、数据质量、数据交换、数据接口、备份恢复和数据生命周期适用于数据处理、托管和门户类服务的技术分类。
云计算、数据中心和运行维护标准类别机房环境、资源池、虚拟化、容器、监控、变更、容量、可用性和故障恢复用于理解运行资源和服务交付条件。
软件产品、版权和交付资料标准类别软件版本、安装包、授权、说明书、接口文档、用户文档和随附资料用于产品化软件和游戏发行边界识别。
互联网内容和平台服务技术规则类别域名、网站、应用分发、内容管理、搜索索引、推荐、广告和用户服务用于门户网站、游戏发行和互联网软件服务事实识别。

F3 通用性法律法规主体

本大类通常涉及著作权、计算机软件保护、合同、电子签名、电子商务、互联网信息服务、网络安全、数据安全、个人信息保护、广告、消费者权益、反不正当竞争、未成年人保护和商业秘密等通用类别。本卡只列类别和边界指针，不给出具体适用性结论；涉及特定互联网内容、出版、新闻、视听、游戏、云服务、数据跨境或专用行业平台的，应由后续受控清单确认实际适用的许可、备案、评估、检测或资料留存要求。

H. 行业本底特征

H1 技术复杂度、自动化与人工依赖程度

其他软件发行技术复杂度取决于产品架构、依赖数量、许可模型、平台数量和客户环境跨度。自动化程度可很高，但版本决策、许可设计、客户沟通、文档维护和兼容性解释仍高度依赖人工经验。

组织形态典型特征常见资源配置

独立软件厂商多产品线和多版本并行发布平台、文档中心、许可服务和支持团队。

H3 客观存在的易出问题环节/技术敏感点

敏感点客观影响链
版本分支混乱开发分支和发行分支不一致 → 安装包功能与文档偏离 → 用户部署问题增加
许可证配置错误模块、期限或账号规则设置不当 → 用户权益无法使用或超范围开放 → 支持争议增加
依赖缺失安装包未包含必要组件 → 客户环境安装失败 → 重新打包和补丁增加
签名证书失效证书过期或签名链异常 → 系统拦截安装 → 用户获取失败
文档滞后功能已变化但说明未同步 → 用户配置错误 → 工单集中
生命周期信息不清旧版本停更口径不明确 → 客户继续部署旧版本 → 兼容和支持压力增加
开源许可证边界不清组件许可证未识别 → 二次发行约束不明确 → 商业交付边界混乱
云订阅权限错配套餐、租户和权限配置不一致 → 用户获得错误功能范围 → 计费和支持问题增加
