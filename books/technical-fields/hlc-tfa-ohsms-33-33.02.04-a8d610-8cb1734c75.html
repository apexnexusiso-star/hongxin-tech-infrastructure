33.02.04 其他信息技术及计算机服务活动，特别是系统集成的内容包含在内 专业小类基础卡

A. 标识与定位

A1 小类名称、分类代码、在分类体系中的位置

字段内容
专业小类代码33.02.04
专业小类名称其他信息技术及计算机服务活动，特别是系统集成的内容包含在内
所属大类33 软件、信息技术、数据处理和互联网门户相关服务
所属中类33.02 信息技术和计算机服务
本卡定位描述系统集成、信息技术实施、软硬件组合、网络和平台联通、迁移割接、联调验收及其他未另分类信息技术服务事实，侧重多供应商、多系统接口和项目交付边界。
与上层文件关系本卡只记录底层行业事实、技术边界、过程、设施、投入、检测计量手段和维护信息，不记录任何上层体系判断。

A2 定义与范围界定

本小类是指未归入编程、咨询、设备管理、数据处理托管和门户网站的其他信息技术及计算机服务活动，其中系统集成是典型内容，通常围绕硬件、软件、网络、数据、平台和接口组合成可运行信息系统。

本小类通常包括系统集成方案实施、软硬件部署、网络集成、平台集成、接口联调、数据迁移、系统割接、运行交付准备、应用配置、项目验收支持和其他综合信息技术服务。

本小类不包括单纯编程开发、纯咨询、长期设备管理、独立数据托管、门户网站运营和标准软件发行。

A3 边界说明：相邻小类区分点与排除项

易混淆活动混淆原因区分依据本卡处理原则
33.01.01 电脑游戏发行都可能涉及软件上架和用户获取游戏发行以游戏作品、玩家账号、补丁和渠道 SDK 为主非游戏服务按自身主导活动识别。
33.02.01 计算机编程活动都可能产生或修改软件编程以受托开发、代码实现和定制交付为主主导输出为代码或定制系统时归编程。
33.02.02 计算机咨询活动都可能提供方案和技术文档咨询以诊断、规划、方案和选型意见为主不直接承担实现或运行时归咨询。
33.02.03 计算机设备管理活动都可能涉及运行维护设备管理以客户计算环境运行和运维为主长期运行托管按设备管理或数据托管识别。
33.02.04 其他信息技术及计算机服务活动系统集成与开发、咨询、运维相邻系统集成以多系统、多设备、多软件互联实施为主按交付对象和责任边界识别。
33.03.01 数据处理、托管及相关活动都可能使用云、服务器和数据数据处理托管以算力、存储、数据作业和托管环境为主独立托管或数据加工归数据处理托管。
33.03.02 门户网站都可能以网站或平台提供服务门户网站以内容入口、检索、聚合、推荐和流量组织为主按内容组织和入口属性识别。

明确排除项包括：纯代码开发、纯咨询报告、长期运维外包、独立机房托管、游戏或软件发行、门户内容服务和硬件制造。

A4 分组特征摘要

受控维度本小类特征摘要
主导活动类型综合信息技术实施和系统集成服务。
交付对象已部署联通的信息系统、软硬件组合、网络拓扑、接口配置、迁移结果、联调记录和交付资料。
核心过程性质方案细化、设备和软件准备、环境部署、接口配置、数据迁移、联调测试、割接上线和验收移交。
主要技术基础网络拓扑、服务器和存储、操作系统、数据库、中间件、API、身份权限、虚拟化、容器和集成测试。
产业链段位位于咨询设计或产品采购之后、系统正式运行之前的实施落地环节。
典型规模跨度从小型局域网和应用部署项目到大型多系统、多地点集成工程。
主要分型轴按网络集成、应用集成、数据迁移、云迁移、弱电智能化、平台实施和行业系统集成分型。
分组比较提示与编程的边界在于多系统部署联通是否主导；与设备管理的边界在于项目交付还是长期运行责任。

B. 术语与概念

B1 专业术语/行话表

术语解释

割接从旧系统或旧环境切换到新系统或新环境的过程。
迁移把数据、应用、配置或运行环境从一处转移到另一处。
拓扑网络、设备或系统组件之间连接关系的结构。
中间件位于操作系统和应用之间提供通信、事务、消息或运行支撑的软件。
接口适配使不同系统按照约定协议、字段和格式互通的过程。
验收环境用于确认系统集成交付状态的测试或准生产环境。
上线窗口实施切换和配置变更允许发生的时间段。
回退方案割接失败时恢复到原状态或备用状态的方案。

B3 关键技术概念说明

系统集成的核心是接口和环境。单个软件或设备可能合格，但组合后仍可能因网络、权限、数据、协议或配置不一致而无法运行。 系统集成活动往往涉及多供应商边界。硬件、操作系统、数据库、中间件、应用、云资源和客户业务部门之间需要清晰的接口资料。 系统集成与编程开发可能同时出现。若项目主导价值在于多系统部署、联通、迁移和割接，应按系统集成识别；若主导价值在于新功能编码，应按编程识别。

D. 过程与技术

D1 主要工艺/过程流程

`mermaid flowchart LR A["项目范围和方案细化"] B["设备软件和环境准备"] C["安装部署和配置"] D["接口联调和数据迁移"] E["集成测试和问题整改"] F["割接上线"] G["验收移交和资料归档"] A --> B B --> C C --> D D --> E E --> F F --> G `

系统集成流程从范围和方案细化开始。实施团队需要把合同、设计、产品资料和现场条件转化为可执行的部署计划和接口清单。 中段过程围绕安装、配置、联调和迁移展开。网络地址、账号权限、数据库连接、中间件参数、接口字段和数据映射共同决定系统能否运行。 后段过程围绕集成测试、割接和验收移交展开。割接窗口、回退方案、问题清单、验收记录和运维资料决定系统从项目状态进入使用状态。

数据迁移源数据、映射规则、清洗规则目标数据和校验结果字段映射、完整性、重复、编码和时间窗口。

D7 系统集成多供应商接口链条补充

系统集成的难点通常不在单个设备或软件本身，而在接口链条。服务器、网络、数据库、中间件、应用、账号、证书、域名、接口字段和数据迁移规则一旦由不同供应商分别负责，就容易出现配置不一致、资料缺口或问题归属不清。识别本小类时，应看组织是否承担把多个组成部分组合成可运行系统的责任；若只是提出方案而不落地，属于咨询；若只是长期运行已上线系统，属于设备管理或托管相关活动。

E. 产业链与边界

E1 上游供应

上游通常包括客户需求、设计咨询、设备和软件供应商、云平台、网络运营商、施工队伍、既有系统资料和数据源。系统集成把分散软硬件和接口资料组合成可运行系统。

E2 下游应用/客户

下游通常包括客户业务使用部门、运维团队、设备管理服务商、数据托管服务商和后续软件开发团队。集成交付后，系统进入运行、维护、扩容和改造阶段。

E3 本小类在产业链中的位置

本小类位于采购、开发和运行之间的实施联通环节，核心是把多种软硬件、网络、数据和接口组合为可运行整体。

E4 常见委外/外包环节

委外/外包环节行业常见原因边界提示
现场施工布线、机柜、安装和环境准备需要专业队伍施工外包需与系统联通责任区分。
设备厂商安装专用设备或软件需厂商授权实施厂商安装不替代总集成协调。
数据迁移数据量大或规则复杂迁移外协需保留规则和比对结果。
网络链路开通运营商或第三方提供线路链路责任需与系统配置分开。
专项联调接口、数据库或中间件需要专门技术支持专项支持需纳入整体问题清单。

E5 典型接口资料与数据流转补充

接口环节常见资料或数据识别价值
方案到实施设计图、设备清单、软件清单、实施计划识别交付输入。
设备到网络端口、IP、VLAN、路由和安全策略识别连通边界。
软件到接口API、账号、证书、数据字段和错误码识别应用连接。
旧系统到新系统迁移规则、源数据、目标数据、比对结果识别切换状态。
项目到运维交付清单、配置、账号、文档、遗留问题识别转维资料。

F. 适用法规与技术标准

F1 行业准入/资质/许可要求

本小类可能涉及增值电信业务、系统集成行业客户要求、网络安全、数据安全、个人信息、密码应用、电子认证、政府采购、招投标、弱电工程和特定行业信息系统建设规则类别。具体适用性由后续受控清单确认。

H. 行业本底特征

H1 技术复杂度、自动化与人工依赖程度

系统集成活动的复杂度取决于软硬件种类、现场条件、接口数量、数据迁移规模、供应商数量和切换窗口约束。工具可辅助部署、测试和迁移，但现场协调、联调定位、回退判断和跨供应商问题处理高度依赖人员经验。

H2 典型组织形态

组织形态典型特征常见资源配置
小型集成商项目区域较小，产品组合有限工程师、实施工具和供应商资源。
行业系统集成商面向政企、金融、制造、教育等行业项目经理、架构师、实施和测试团队。
弱电信息集成商现场施工和平台联动并重施工队伍、图纸、设备和现场管理。
云迁移实施团队云资源、网络和数据迁移突出云平台账号、迁移工具和脚本。
厂商生态集成团队围绕特定产品线实施授权工程师、产品文档和实验环境。

H3 客观存在的易出问题环节/技术敏感点

敏感点客观影响链
现场条件变化电源、机柜、网络或窗口与方案不一致 → 实施调整增加 → 交付延期
接口资料不完整字段、协议或账号缺失 → 联调失败 → 问题定位周期延长
配置未按设计落地现场参数与设计偏离 → 系统行为异常 → 后续维护困难
迁移规则错误源目标字段映射不清 → 数据偏差 → 业务切换受阻
供应商责任重叠多方设备和软件交界不清 → 问题归属争议 → 闭环变慢
回退条件不足切换失败后缺少回退步骤 → 服务中断时间延长 → 客户影响扩大
交付资料缺项账号、配置、图纸和版本清单不完整 → 运维接手困难 → 后续故障增加
遗留问题不闭环限制项和待办未跟踪 → 系统带病运行 → 改造成本上升

H3 只记录行业中客观存在的敏感点及事实因果链，不对其在任何上层视图中的重要性作判断。
