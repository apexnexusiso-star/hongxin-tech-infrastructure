  • 文件定位说明

本文件用于质量管理体系认证中 QG29-2 技术领域包的分组论证、审核员专业能力评价、授权控制、项目匹配、能力扩展和持续保持。文件聚焦汽车保养修理和摩托车销售保养维修复合服务在 QMS 轴下的质量形成链、客户要求转化、关键质量特性、检验放行、记录追溯、投诉反馈和改进闭环。本文件不承担行业百科说明功能，基础行业事实由对应专业小类基础卡承载。

本组采用“统一维修服务领域包 + 汽车/摩托车分支标注 + 安全关键维修专项确认 + 条件扩展”的使用口径。组内小类可以共享通用商业服务质量管理判断方法，但不得把某一商品、服务或渠道分支经历等同于另一分支完整能力；对特殊商品、复杂服务、法定接口或高价值交付，应追加分支确认。

小类编码小类名称纳入本包的活动范围主要内部路线特殊边界

  • 分组设立的基本逻辑

本包在 QMS 轴下的共同对象是以车辆故障、保养需求或骑行安全需求为输入的诊断、维修、配件和修后确认服务。质量管理体系审核关注的核心不是商品名称或服务名称是否完全相同，而是客户需求如何被识别和转化，商品或服务对象如何受控，交易、工单或订单过程如何记录，交付前后如何检验或确认，客户反馈如何形成闭环。

本包可概括的共同质量形成链为：客户报修或保养需求 -> 接车检查和故障诊断 -> 工单和报价确认 -> 配件和工具准备 -> 维修或保养实施 -> 过程检验和修后测试 -> 交车说明 -> 返修、投诉和质保闭环。该链条决定了本包共享的专业能力基础，即审核员应能够围绕客户要求、商品或服务对象、过程记录、输出验证、交付确认和反馈闭环建立审核证据链。

组内差异主要表现为车辆结构、动力系统、维修设备、作业深度和客户使用场景不同。汽车维修覆盖乘用车、商用车、钣喷和复杂电控系统；摩托车活动通常同时包含销售、维修和配件服务，关注发动机、传动、制动、轮胎、骑行装备和轻量化交付。这些差异不否定设组，但要求本包不能按无差别能力包使用，应通过分支标注、专项确认、条件扩展和抽样控制加以处理。

共同能力维度本包共同基础可共享的审核判断不能共享的边界
客户需求和故障识别均以客户描述、车辆状态、里程、故障现象和保养计划作为输入。可共享接车问诊、检查、故障确认和客户授权判断。商用车、摩托车、动力电池和高压系统诊断差异需确认。
工单和过程控制均需形成工单、报价、配件、人员、工位、设备和过程检验记录。可共享维修工单、配件领用、作业步骤和主管复核判断。钣喷、机电、轮胎、制动和发动机深度维修不能互相替代。
配件和材料适配均依赖配件型号、适配性、来源、库存和领用记录。可共享配件识别、替换件控制和不合格配件处置判断。安全关键件、改装件、摩托车骑行装备和高压部件需专项确认。
修后检验和放行均需通过路试、功能测试、仪器检测、外观检查或客户验收支撑交车。可共享修后确认、交车说明和质保承诺判断。高压系统、制动转向、商用车负载和摩托车骑行安全测试差异明显。
返修和投诉闭环均需记录返修、客户投诉、质量问题和改进措施。可共享返修率、原因分析、技师能力和过程改进判断。重复故障和安全关键返修应提高样本深度。
  • 本体系核心控制要求

本组所称关键质量特性，是指商品或服务输出中影响客户可接受性的适配性、真实性、完整性、及时性、一致性、可追溯性、功能状态、数量准确性和售后响应。商业服务场景中的检验和放行，通常表现为订单复核、商品验收、库存盘点、称量计量、温度或效期检查、工单复核、交付签收、客户确认、主管抽查或质检记录。审核员应把这些复核和确认活动作为服务结果进入客户使用前的质量控制证据。

第一，应确认接车和故障诊断过程。审核样本应覆盖客户报修、接车检查、故障描述、初步诊断、报价和客户授权。诊断不充分会导致维修范围偏差、费用争议和返修。

第二，应追溯维修过程和配件控制。汽车与摩托车维修均需控制工单、维修人员、维修设备、配件领用、过程检验和异常记录。安全关键件应能说明型号适配、来源、安装过程和修后确认。

第三，应评价修后检验和放行。普通保养、制动维修、轮胎更换、电气故障、发动机维修、钣喷维修和摩托车传动系统维修的放行证据不同；审核员应确认放行依据与维修内容匹配，而不是只看交车签字。

第四，应核查客户交付和售后闭环。交车说明、质保承诺、返修记录、客户投诉和技师能力改进是维修服务质量形成的后端证据。对重复返修和安全关键返修，应追溯原因分析和纠正措施有效性。

小类/路线与本包共同基础主要差异差异对能力授权的影响控制方式
29.02.00 汽车的保养和修理共享接车、诊断、工单、配件、维修、测试和交车基础。乘用车、商用车、钣喷、电控、高压和安全关键系统复杂度较高。应标注汽车维修分支；复杂系统需专项确认。抽取维修工单，追溯诊断、配件、维修、测试和返修。
29.04.00 摩托车的销售、保养、维修及零部件和配件的销售共享维修服务和零配件适配基础。销售、维修和配件一体化，骑行安全部件和轻型车辆使用场景突出。应标注摩托车分支；销售与维修复合项目需双样本。抽取整车交付和维修工单，追溯配件适配、修后试车和客户反馈。
快修保养路线共享工单和修后确认基础。流程短、批量高、换油轮胎制动等标准化项目多。可作为维修基础能力，不能覆盖深度诊断。抽取保养样本和返修样本。
机电深度维修路线共享诊断和配件控制基础。电控、发动机、传动、故障诊断和专用设备要求高。从快修扩展需条件确认。故障诊断案例、维修方案和测试记录评审。
钣喷和车身修复路线共享工单、材料和交付基础。车身测量、喷涂、色差、外观和保险定损接口突出。应单独标注钣喷分支。钣喷工单、色号、喷涂过程、外观交付和返修记录抽样。
安全关键维修路线共享维修过程控制基础。制动、转向、高压、电池、燃油和轮胎直接影响使用安全。属于专项确认路线。见证审核、专项案例、技术专家面谈。
  • 分组合理性论证结论

本组可以设立的理由在于，汽车和摩托车相关维修活动均围绕车辆使用状态恢复和客户交付确认形成质量，均需要控制接车诊断、工单、配件、维修实施、修后检验、交车和返修闭环。差异可通过汽车/摩托车分支标注、维修深度标注和安全关键专项确认控制。

因此，QG29-2 可以作为质量管理体系技术领域包使用，但其使用方式应为“统一维修服务领域包 + 汽车/摩托车分支标注 + 安全关键维修专项确认 + 条件扩展”。审核员授权、项目匹配和能力扩展均应体现分支差异，不得把同包经历理解为跨全部小类的充分证明。

  • 审核关键要点与抽样方法
抽样场景现场必看记录必查纵向追溯路径追问方向
汽车机电维修维修工位、诊断设备、配件区、试车区。接车单、诊断记录、报价、配件领用、维修记录、测试和交车记录。报修 -> 诊断 -> 工单 -> 维修 -> 测试 -> 交车 -> 返修。诊断依据如何形成；修后测试是否覆盖故障。
摩托车维修门店、维修工位、配件柜、试车区域。接车、配件、维修、试车、客户签收和质保记录。客户需求 -> 工单 -> 配件 -> 维修 -> 试车 -> 交付。骑行安全部件如何确认。
钣喷维修钣金区、喷漆区、调色和烘干设备。定损、维修方案、材料、喷涂过程、外观检验和返修记录。事故输入 -> 定损 -> 修复 -> 喷涂 -> 外观验收。色差和外观缺陷如何控制。
安全关键件更换制动、轮胎、转向或高压工位。配件适配、安装扭矩或工艺、过程检验、路试或功能测试。客户需求 -> 配件确认 -> 安装 -> 测试 -> 交付。放行依据是否充分。

  • 培训、考核与作业指导书需求

本组应建立机动车和摩托车维修 QMS 培训，内容包括接车问诊、故障诊断、工单管理、配件适配、维修过程、专用设备、修后检验、路试或功能测试、交车说明、返修和投诉闭环。分支培训应覆盖汽车、商用车、摩托车、快修保养、机电深度维修、钣喷和安全关键维修。

考核宜采用场景式题目和案例追溯题，要求审核员能够从一个真实或模拟订单、交易、工单或交付样本出发，说明客户要求识别、资源配置、关键过程控制、输出复核、交付验收、投诉反馈和纠正措施之间的证据关系。作业指导书宜提供分支化抽样路径、典型记录清单、访谈问题库和授权边界提示。

  • 常见合规义务类别与标准适用提示

本组可能涉及机动车维修经营、配件来源和标识、计量设备、废旧配件处置、消费者权益、价格和合同、车辆安全相关部件、保险理赔接口、道路车辆服务、个人信息和客户行业专项要求等类别。文件不列具体标准编号和年份；适用性应使用机构受控的有效清单、客户合同、服务目录、项目范围和所在地监管要求确认。上述类别用于识别外部要求如何转化为客户要求、商品控制、服务过程、记录保存、客户沟通和输出复核，不替代政府许可、行政执法或客户专项验收。

  • 分组使用限制和法定边界

本组的 QMS 分组不替代机动车维修经营备案或许可判断、道路交通安全监管、车辆强制检验、特种设备或计量法定检定、保险定损结论、车辆安全责任认定或司法判断。涉及高压电、动力电池、制动转向、商用车、改装、事故车和复杂电子控制系统时，应确认对应分支能力。

管理体系审核仅用于评价组织是否在其服务范围内建立并实施质量管理控制，不替代行政许可、法定检验、行政执法、政府监管、司法判断、强制检验、产品准入、计量检定、食品药品监管、烟草专卖监管、危险化学品经营监管、特种商品管理或其他法定结论。涉及受监管资质、特殊商品、个人信息、资金、现场作业和外包服务时，应在项目匹配阶段确认审核员分支能力和必要的技术支持。

  • 分组结论与使用口径

QG29-2 可作为质量管理体系机动车和摩托车维修服务技术领域包使用。授权时应记录汽车维修、摩托车维修、快修保养、机电深度维修、钣喷和安全关键维修等分支能力。文件维护触发条件包括：车辆技术路线、维修设备、动力电池和高压系统、维修经营边界、配件供应方式或基础卡信息发生实质变化。
