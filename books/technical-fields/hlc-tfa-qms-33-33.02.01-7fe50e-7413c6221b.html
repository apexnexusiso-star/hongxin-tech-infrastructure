33.02.01 计算机编程活动 专业小类基础卡

A. 标识与定位

A1 小类名称、分类代码、在分类体系中的位置

字段内容
专业小类代码33.02.01
专业小类名称计算机编程活动
所属大类33 软件、信息技术、数据处理和互联网门户相关服务
所属中类33.02 信息技术和计算机服务
本卡定位描述受托软件开发、应用系统开发、接口开发、代码实现、构建测试和交付转维的行业事实，侧重需求到代码、构建物、测试和交付资料的技术链条。
与上层文件关系本卡只记录底层行业事实、技术边界、过程、设施、投入、检测计量手段和维护信息，不记录任何上层体系判断。

A2 定义与范围界定

本小类是指根据客户、产品或内部业务需求开展计算机软件的需求分析、架构设计、程序编码、接口实现、数据库设计、测试、构建、部署准备和技术文档形成的活动。

本小类通常包括应用软件开发、网站和移动应用开发、后端服务开发、接口开发、数据库开发、脚本开发、系统二次开发、软件维护性开发和定制软件项目。

本小类不包括标准软件发行、单纯计算机咨询、系统集成实施、客户计算设施长期管理、数据处理托管和门户网站内容运营。

A3 边界说明：相邻小类区分点与排除项

易混淆活动混淆原因区分依据本卡处理原则
33.01.01 电脑游戏发行都可能涉及软件上架和用户获取游戏发行以游戏作品、玩家账号、补丁和渠道 SDK 为主非游戏服务按自身主导活动识别。
33.02.01 计算机编程活动都可能产生或修改软件编程以受托开发、代码实现和定制交付为主主导输出为代码或定制系统时归编程。
33.02.02 计算机咨询活动都可能提供方案和技术文档咨询以诊断、规划、方案和选型意见为主不直接承担实现或运行时归咨询。
33.02.03 计算机设备管理活动都可能涉及运行维护设备管理以客户计算环境运行和运维为主长期运行托管按设备管理或数据托管识别。
33.02.04 其他信息技术及计算机服务活动系统集成与开发、咨询、运维相邻系统集成以多系统、多设备、多软件互联实施为主按交付对象和责任边界识别。
33.03.01 数据处理、托管及相关活动都可能使用云、服务器和数据数据处理托管以算力、存储、数据作业和托管环境为主独立托管或数据加工归数据处理托管。
33.03.02 门户网站都可能以网站或平台提供服务门户网站以内容入口、检索、聚合、推荐和流量组织为主按内容组织和入口属性识别。

明确排除项包括：标准软件产品发行、游戏发行、纯咨询报告、硬件安装、数据中心托管、门户内容采编和硬件设备维修。

A4 分组特征摘要

受控维度本小类特征摘要
主导活动类型软件工程开发和代码交付活动。
交付对象源代码、可执行构建物、接口、数据库脚本、配置文件、测试记录和技术文档。
核心过程性质需求澄清、架构设计、编码、代码评审、构建、测试、缺陷修复、部署准备和转维交接。
主要技术基础编程语言、框架、数据库、API、版本控制、CI/CD、自动化测试、代码静态分析和配置管理。
产业链段位位于业务需求和软件可运行系统之间的技术实现环节。
典型规模跨度从个人开发者、小型项目组到大型多团队敏捷研发组织。
主要分型轴按定制/产品研发、前端/后端/移动/嵌入式/低代码、瀑布/敏捷/DevOps 分型。
分组比较提示与软件发行的边界在于是否主导代码实现；与系统集成的边界在于是否以多系统部署互联为主。

B3 关键技术概念说明

编程活动的核心是把需求和设计转化为可运行的软件逻辑。交付物不仅是代码，还包括构建方式、配置、测试结果、接口说明和交接资料。 源代码和构建物之间存在可追溯关系。代码分支、依赖版本、编译参数、环境变量和配置文件的差异，会导致同一需求形成不同运行状态。 编程活动与咨询的边界在于是否承担实现；与系统集成的边界在于是否以多产品部署、联通和现场交付为主。

D. 过程与技术

D1 主要工艺/过程流程

`mermaid flowchart LR A["需求输入"] B["需求分析和原型"] C["架构与详细设计"] D["编码和代码评审"] E["构建与自动化测试"] F["缺陷修复和版本冻结"] G["部署资料和转维交接"] A --> B B --> C C --> D D --> E E --> F F --> G `

计算机编程流程从需求输入开始。需求可能来自客户合同、产品路线、运维问题或数据接口变更，开发团队需要把业务语言转化为功能、数据、接口和约束。 中段过程围绕代码实现展开。开发人员使用编程语言、框架、数据库和第三方组件形成源代码，通过代码仓库、分支、合并、构建和测试形成可运行制品。 后段过程围绕缺陷修复、版本冻结和转维交接展开。测试结果、部署脚本、配置说明、接口文档和运行注意事项决定软件能否从开发状态进入使用状态。

D2 关键过程、特殊过程

过程环节主要输入主要输出技术控制点
需求澄清业务需求、用户故事、合同、原型需求规格和范围边界功能、约束、优先级、验收条件和变更记录。
架构设计需求、技术约束、现有系统、数据模型架构图、接口设计、数据库设计组件划分、接口契约、部署拓扑和技术选型。
编码实现设计、框架、库、编码规范源代码和配置分支、命名、异常处理、日志和安全编码。
代码评审合并请求、代码差异、检查规则评审记录和修改项可读性、重复逻辑、边界条件和依赖变化。
构建打包源代码、依赖、构建脚本、环境变量可执行制品构建可重复性、依赖版本和制品标识。
测试验证测试用例、测试数据、环境测试结果和缺陷单单元、集成、接口、性能和回归覆盖。
缺陷修复缺陷单、日志、复现数据修复代码和回归结果根因、影响范围、回归和版本归属。
交付转维制品、文档、配置、脚本部署包和交接资料部署步骤、配置项、回滚和支持边界。

D2 关注的是过程本身需要控制的技术对象；H3 关注行业中客观上容易出现问题的环节及其事实因果链，二者不互相替代。

类别常见设备/设施/工具用途
开发工作站和集成开发环境IDE、代码编辑器、插件、调试器、本地运行环境代码编写、调试和本地验证。
代码仓库和分支管理工具Git 仓库、分支策略、合并请求、标签和发布分支保存源代码并追溯修改历史。
构建和制品管理平台构建服务器、CI/CD 流水线、制品库、镜像仓库形成可重复构建物。
测试环境和自动化工具单元测试、接口测试、性能测试、移动端兼容环境验证软件功能和运行约束。
缺陷和需求管理系统需求池、缺陷单、任务板、迭代计划、知识库连接需求、代码、测试和交付资料。
数据库和中间件环境开发库、测试库、缓存、消息队列、接口模拟器支撑应用逻辑和接口联调。

D3 关注的是设备、设施、工具作为过程资源的客观配置；G 段关注用这些资源或外部资源测量哪些参数、采用哪些方法，二者分别维护。

D4 主要原辅材料与投入

投入类别常见投入技术特征
业务需求合同、用户故事、原型、业务规则、验收条件确定软件实现范围。
设计资料架构图、接口设计、数据模型、页面设计支撑编码和测试。
源代码和依赖代码仓库、框架、第三方库、组件清单形成构建输入。
测试资料测试用例、测试数据、缺陷单、回归清单支撑验证和修复。
配置资料环境变量、部署参数、证书、密钥占位、连接串决定运行状态。
变更资料变更请求、版本计划、影响分析、发布说明连接迭代和交付。

D5 常见过程路线或服务路线差异

路线典型组织形态差异说明
客户定制开发按单个客户需求形成系统或模块需求边界、变更和交付资料更突出。
产品研发开发围绕自有产品路线持续迭代版本分支、缺陷池和兼容性更突出。
接口和中间层开发连接多个系统或数据源协议、字段、鉴权和错误码更突出。
低代码/配置开发使用平台组件和配置模型实现功能平台约束、配置版本和扩展代码更突出。
维护性开发在既有系统上修复或扩展影响范围、回归和技术债更突出。

D6 典型路线识别提示

识别对象典型信息技术含义
代码仓库分支、提交、标签、合并记录识别开发活动和版本来源。
构建脚本依赖文件、流水线、镜像配置识别制品生成方式。
测试资料用例、覆盖、缺陷、回归记录识别验证边界。
接口文档字段、协议、错误码、鉴权方式识别系统间契约。
部署资料配置、脚本、环境说明、回滚步骤识别运行转换条件。
变更记录需求变更、缺陷修复、版本说明识别迭代轨迹。

D7 需求、代码、构建和部署链条补充

编程活动不能只看作“写代码”。真正的链条是需求如何进入设计，设计如何进入代码，代码如何进入构建，构建如何进入测试和部署。若只有代码而没有构建脚本、依赖说明、配置项和测试结果，后续使用者难以复现运行状态。若组织主要提供方案蓝图而不承担编码实现，应转向咨询活动；若主要把第三方软硬件部署联通，应转向系统集成活动。

E. 产业链与边界

E1 上游供应

上游通常包括客户业务部门、产品经理、设计团队、架构团队、第三方平台、开源组件、云资源、数据库和既有系统资料。编程活动把这些输入转化为代码、配置、测试和可运行制品。

E2 下游应用/客户

下游通常包括系统集成实施方、运维团队、软件发行方、客户业务用户、测试团队和平台运营方。编程成果进入部署、集成、运行、维护或产品发行环节。

E3 本小类在产业链中的位置

本小类位于需求和可运行软件之间，是信息技术服务链条中的技术实现环节。它不以渠道发行、咨询判断、长期托管或门户内容组织为主。

E4 常见委外/外包环节

委外/外包环节行业常见原因边界提示
界面设计专业交互和视觉资源需求较强设计外包不改变编码实现主体。
专项测试性能、安全、兼容或移动端设备覆盖需要专门资源测试外包应保留用例和结果边界。
组件开发某些模块可由外部团队完成接口、代码归属和集成责任需识别。
技术文档复杂系统需要专门文档整理文档外包不替代代码和配置管理。
部署环境准备开发方可能借助云平台或运维团队环境准备与软件实现责任需要区分。

E5 典型接口资料与数据流转补充

接口环节常见资料或数据识别价值
需求到设计需求清单、原型、架构图、数据模型识别需求如何被技术化。
设计到代码任务、分支、模块、接口契约识别实现路径。
代码到构建仓库、依赖、脚本、流水线识别制品来源。
测试到修复缺陷单、日志、复现数据、回归结果识别闭环状态。
开发到部署制品、配置、脚本、交接说明识别转维边界。

F. 适用法规与技术标准

F1 行业准入/资质/许可要求

本小类通常涉及软件著作权、合同交付、开源组件许可、个人信息和数据处理、加密功能、特定行业应用接口、电子签名或平台上架等类别。具体适用性由后续受控清单确认。

F2 强制性产品标准、主要国家/行业技术标准

标准类别可能覆盖内容本卡处理方式
软件工程与软件生命周期标准类别需求、设计、编码、测试、配置、发布、维护、文档和项目过程作为软件过程事实和术语来源类别记录，具体编号由受控清单核验。
信息安全与网络安全技术标准类别身份鉴别、访问控制、加密、日志、漏洞、备份、连续性和安全配置仅作为信息技术事实来源类别，具体适用性由项目资料确认。
数据管理与数据服务标准类别数据模型、元数据、数据质量、数据交换、数据接口、备份恢复和数据生命周期适用于数据处理、托管和门户类服务的技术分类。
云计算、数据中心和运行维护标准类别机房环境、资源池、虚拟化、容器、监控、变更、容量、可用性和故障恢复用于理解运行资源和服务交付条件。
软件产品、版权和交付资料标准类别软件版本、安装包、授权、说明书、接口文档、用户文档和随附资料用于产品化软件和游戏发行边界识别。
互联网内容和平台服务技术规则类别域名、网站、应用分发、内容管理、搜索索引、推荐、广告和用户服务用于门户网站、游戏发行和互联网软件服务事实识别。

H. 行业本底特征

H1 技术复杂度、自动化与人工依赖程度

计算机编程活动的复杂度取决于业务规则复杂性、代码规模、技术栈数量、接口依赖、数据模型、团队协作和部署环境跨度。自动化工具可覆盖构建、测试和部署，但需求理解、架构权衡、边界条件识别、缺陷定位和技术债处理仍高度依赖人员经验。

组织形态典型特征常见资源配置

项目型软件公司多客户定制项目并行项目管理、配置管理、测试和交付团队。

外包协作团队跨组织分工和接口交付突出任务边界、仓库权限、代码交接和文档。

H3 客观存在的易出问题环节/技术敏感点

敏感点客观影响链
需求边界不清需求表述模糊 → 设计和代码理解不一致 → 返工和交付争议增加
依赖版本漂移库和框架版本未锁定 → 构建环境差异 → 运行状态不可复现
接口契约不稳定字段或协议频繁变化 → 上下游系统调用失败 → 联调周期延长
测试数据不足边界数据和异常数据缺失 → 缺陷未暴露 → 上线后问题集中
配置资料缺失环境参数未记录 → 部署无法复现 → 运行故障定位困难
分支管理混乱开发、测试和发布分支关系不清 → 代码合并错误 → 版本内容偏离
技术债累积短期实现绕开架构约束 → 修改成本上升 → 后续迭代变慢
转维资料断点脚本、日志和支持边界不清 → 运行团队接手困难 → 故障恢复时间延长
