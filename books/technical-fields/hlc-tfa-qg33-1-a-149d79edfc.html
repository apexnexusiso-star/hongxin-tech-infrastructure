  • 文件定位说明

本文件用于质量管理体系认证中 QG33-1 技术领域包的分组论证、审核员专业能力评价、授权控制、项目匹配、能力扩展和持续保持。文件聚焦软件发行活动在 QMS 轴下的质量形成、版本控制、渠道交付、检验放行、追溯反馈和客户支持，不承担软件行业百科说明功能。

本文件采用“统一领域包 + 游戏发行分支 + 通用软件发行分支 + 条件扩展 + 边界受控”的使用口径。对电脑游戏发行和其他软件发行的共同能力可以共享基础评价，但不得把一个分支经历理解为另一个分支的完整能力证明。

  • 技术领域包构成
小类编码小类名称纳入本包的活动范围主要内部路线特殊边界
33.01.01电脑游戏发行电脑客户端游戏、联网游戏、单机游戏数字发行、代理发行、版本包、补丁、资料片、渠道上线、账号和用户支持接口。自研自发、代理发行、平台发行、持续运营型发行、引进或跨区域发行。游戏内容资产、玩家账号、支付接口、反作弊、服务器版本和渠道 SDK 会显著影响质量形成链。
33.01.02其他软件发行现成软件、操作系统、商业软件、工具软件、企业软件、云订阅软件、开源商业版本的版本发布、许可、安装包、文档和支持。传统安装包发行、企业批量授权、应用市场发行、云订阅发行、开源商业发行。企业许可、组件清单、安装环境、签名、升级回滚和生命周期公告是主要边界。
  • 分组设立的基本逻辑

本包的共同对象是可交付的软件版本。无论电脑游戏还是其他软件，QMS 关注的核心均是：顾客和市场要求如何转化为版本发布要求，源制品或内容资源如何形成可交付包，检验和验证如何支持放行，渠道交付后如何保持版本可追溯并处理用户反馈。

本包的共同质量形成链可概括为：需求和发布计划 → 版本冻结 → 构建或打包 → 签名、授权和渠道适配 → 测试验证 → 发布放行 → 下载、安装或账号启用 → 用户反馈、补丁和更新闭环。该链条决定了软件发行活动的共同专业能力基础。

电脑游戏发行在内容资产、玩家账号、补丁节奏、渠道 SDK、反作弊和在线服务器协同方面更加突出；其他软件发行在许可证、安装环境、企业部署、组件清单、兼容性和生命周期支持方面更加突出。上述差异不否定设组，但应通过分支能力标注、项目匹配和条件扩展控制。

  • 专业小类关系类型与授权后果
关系类型含义授权后果典型控制方式
共同基础关系共享信息技术服务、需求识别、版本或配置控制、验证放行和反馈闭环等基础能力。可简化基础专业面谈，但仍应确认目标小类或目标路线的实际经历。资料评审、案例判断、专业面谈。
并列分支关系同属本技术领域包，但交付对象、过程重点或质量形成路径存在分支差异。应记录实际分支能力，不把同包经历理解为全分支能力。分支标注、限定使用、项目技术支持。
条件扩展关系已具备相邻分支能力，具备扩展基础，但目标路线仍有专门知识和证据要求。完成补充培训、案例评审、专业面谈或见证审核后方可扩展。培训考核、案例评审、见证审核。
专项确认关系涉及特殊平台、强内容属性、高可用服务、大规模数据或复杂集成边界。在项目使用前应进行专项确认，必要时配置技术专家支持。专项面谈、技术专家评审、项目前确认。
不可直接替代关系相关 IT 经历不足以证明目标小类的质量形成链能力。不得作为目标能力的单独授权依据。重新评价、补充经历或限定项目类型。
边界受控关系互联网服务、数据、内容、账号、版权、许可或客户行业要求改变使用边界。授权记录应写明边界，项目匹配时按实际服务内容确认。授权备注、合规类别清单、技术支持。
游戏发行与其他软件发行二者共享版本、渠道、许可、测试、放行和支持闭环。可共享软件发行基础评价，但应标明游戏发行或通用软件发行分支。以一项完整发行案例进行面谈和证据追溯。
联网游戏发行专项确认联网游戏涉及服务器版本、账号、支付、反作弊和高频更新。仅有单机软件发行经历不足以承担复杂联网游戏发行项目。补充游戏发行案例、渠道 SDK 和版本更新链条确认。
企业软件发行边界受控企业软件涉及批量授权、客户环境、升级回滚和技术支持。仅有游戏发行经历扩展时应确认企业部署和许可管理能力。企业部署包、许可证和客户支持案例评审。
  • 本体系共同能力基础
共同能力维度本包共同基础可共享的审核判断不能共享的边界
顾客要求转换把市场、客户、平台、合同、用户场景和发布目标转换为版本要求。能判断发布计划、版本范围、渠道资料和用户说明是否一致。游戏玩法、内容资源、企业客户部署约束需要分支确认。
版本和配置控制均需控制版本号、构建号、发布分支、补丁、依赖和发行说明。能追溯一个发布版本从冻结到放行的证据链。服务器端版本、渠道 SDK、企业许可服务器等差异不能简单互认。
检验验证和放行均需通过安装、兼容、功能、升级、回滚、签名或授权验证支撑放行。能判断放行前验证是否覆盖主要使用场景。游戏平衡、反作弊、在线匹配、企业批量部署等验证对象需专项判断。
交付和渠道控制均通过官网、平台、应用市场、企业客户或云入口交付给用户。能检查渠道资料、交付包、签名、许可和用户文档的一致性。不同渠道规则和上线资料差异需要按项目确认。
追溯和反馈闭环均需保留发布记录、用户问题、补丁记录、生命周期公告和支持工单。能沿一个用户问题追溯到版本、渠道、补丁和关闭记录。玩家运营反馈和企业服务支持的指标口径不同。
  • 本体系核心控制要求

本章所称关键质量特性，是指服务或软件交付结果中影响顾客可接受性的功能、性能、可用性、完整性、可追溯性、服务响应和交付一致性等特性。

QMS 审核应围绕软件发行质量形成链展开。第一，应核对顾客要求、发布计划、平台要求、版本范围和放行准则是否被识别并转化为可执行的发布任务。第二，应核对发布分支、构建物、资源包、组件清单、安装包、签名和许可证配置是否受控。第三，应核对测试验证是否覆盖安装、升级、兼容、授权、性能、回滚、渠道接入和用户主要场景。第四，应核对放行记录是否能够说明版本状态、已知问题、限制条件和批准责任。第五，应核对用户反馈、缺陷、补丁和生命周期公告是否形成闭环。

对游戏发行，应增加客户端与服务器协议、补丁资源包、账号登录、渠道 SDK、支付接口、反作弊组件、玩家数据迁移和版本灰度的质量控制。对其他软件发行，应增加企业客户环境、安装文档、许可模型、组件依赖、开源许可证边界、升级回滚和长期支持期限的质量控制。

  • 分小类或内部路线差异分析
小类/路线与本包共同基础主要差异差异对能力授权的影响控制方式
33.01.01 电脑游戏发行版本、渠道、许可、测试、放行和用户支持与软件发行共享。内容资产、玩家账号、渠道 SDK、服务器版本、反作弊和补丁节奏突出。应标注游戏发行分支；复杂联网游戏应专项确认。游戏发行案例面谈、版本更新链追溯、渠道接入资料确认。
33.01.02 其他软件发行版本包、许可、安装、升级、文档和客户支持链条共享。企业部署、许可证、兼容环境、组件清单和生命周期支持突出。应标注通用软件发行分支；企业软件或云订阅需确认对应经历。企业部署包、许可证和升级回滚案例评审。
单机游戏发行与软件安装包发行接近。内容资源和平台上架资料仍具有游戏属性。可作为游戏发行基础经历，但不足以覆盖复杂联网游戏。限定分支，补充联网游戏或运营型发行确认。
联网游戏发行共享版本发布和用户支持基础。服务器、账号、支付、反作弊、热更新和容量更突出。属于专项确认路线。技术专家面谈、见证审核、服务器版本和补丁链条追溯。
云订阅软件发行共享版本、许可和用户支持基础。在线租户、套餐、权限、持续更新和服务可用性更突出。从传统软件扩展时需补充在线服务能力。SaaS 发布案例、权限配置和服务状态记录评审。
开源商业软件发行共享版本和文档交付基础。第三方组件、许可证边界、商业支持和社区版本关系突出。应确认组件清单和许可资料能力。组件清单、许可边界和发行说明案例评审。
  • 分组合理性论证结论

本组可以设立的理由在于两个小类均以软件版本发行作为质量形成核心，均依赖版本控制、配置管理、验证放行、渠道交付、许可或账号控制、用户反馈和补丁维护。QMS 审核员掌握其中一个分支后，能够共享软件发行基础判断方法。

同时，本组不得按无差别能力包使用。电脑游戏发行和其他软件发行在交付对象、用户行为、渠道接口和质量验证重点上存在实质差异。机构使用本组时应采用“统一领域包 + 分支能力标注 + 条件扩展 + 专项边界控制”的口径。

  • 审核关键要点与抽样方法
抽样场景现场必看记录必查纵向追溯路径追问方向
一次软件版本发布版本库、制品库、发布会议或发布看板、放行入口。发布计划、构建记录、测试报告、放行批准、发行说明。发布需求 → 版本冻结 → 构建包 → 测试验证 → 放行 → 渠道交付 → 用户反馈。版本范围如何确定；已知问题如何决定是否放行；回滚条件如何设置。
游戏补丁或资料片资源包、补丁系统、启动器、渠道后台、用户反馈入口。补丁清单、兼容测试、服务器版本记录、灰度记录、问题工单。玩家问题或版本需求 → 补丁开发输入 → 资源打包 → 渠道适配 → 更新放行 → 运行反馈。客户端和服务器版本如何匹配；异常补丁如何回退；玩家数据如何保护。
企业软件交付包安装包、许可证配置、用户文档、客户支持入口。客户要求、兼容矩阵、安装验证、授权记录、升级和回滚说明。客户合同 → 产品版本 → 安装验证 → 许可启用 → 用户验收 → 支持工单。客户环境差异如何识别；许可证变更如何追溯；文档如何随版本同步。
云订阅软件发布租户后台、套餐配置、服务状态页、权限模型。变更记录、租户配置、发布窗口、监控和用户通知记录。发布计划 → 在线配置 → 权限验证 → 服务监控 → 用户反馈。不同租户如何隔离；在线变更如何控制；服务异常如何通知。
用户投诉闭环客服系统、缺陷系统、版本记录、补丁计划。投诉记录、问题分类、根因分析、修复版本、关闭验证。用户问题 → 版本定位 → 缺陷确认 → 补丁或说明 → 用户关闭。问题是否重复发生；是否触发版本或流程改进。
  • 能力扩展与条件授权
起点能力目标能力可扩展依据必须补充确认授权限制
其他软件发行电脑游戏发行共享版本、渠道、许可、测试和用户支持基础。游戏内容资产、玩家账号、渠道 SDK、补丁、反作弊和服务器协同案例。未确认前限用于非复杂游戏或在技术支持下使用。
电脑游戏发行其他软件发行共享版本包、渠道发布和用户反馈闭环。企业部署、许可证、组件清单、安装升级和生命周期支持案例。未确认前不得用于复杂企业软件发行项目。
单机游戏发行联网游戏发行共享游戏版本和渠道发布基础。服务器版本、账号、支付、反作弊、灰度和运行反馈。应经专项确认后使用。
传统安装包发行云订阅软件发行共享软件版本和用户支持基础。租户、权限、服务可用性、在线变更和状态报告。限定云订阅服务复杂度，必要时配置专家支持。
开源商业版本发行闭源商业软件发行共享版本、文档、发布和支持基础。商业许可、客户环境、安装验证和升级回滚资料。按实际产品类型标注分支。
  • 培训、考核与作业指导书需求

本组应建立软件发行 QMS 专业培训，内容包括软件版本生命周期、发布分支、构建和制品库、签名和许可证、安装升级、渠道交付、用户文档、缺陷和补丁闭环。游戏发行分支应增加游戏版本包、内容资源、渠道 SDK、账号支付、反作弊、客户端与服务器协同、灰度发布和玩家反馈。其他软件发行分支应增加企业部署、组件依赖、许可证模型、安装验证、升级回滚、生命周期公告和客户支持。

考核宜采用案例式题目，要求审核员能够沿一个发布版本或一个用户问题追溯需求、版本、测试、放行、渠道和反馈。作业指导书应提供发布版本抽样路径、补丁抽样路径、许可证抽样路径和用户反馈闭环抽样路径。

  • 常见合规义务类别与标准适用提示

本组可能涉及软件著作权、网络出版、游戏内容管理、互联网信息服务、个人信息保护、数据安全、网络安全、电子合同、消费者权益、广告、未成年人保护、知识产权、开源组件许可、应用市场规则和客户行业专门要求等类别。文件不列具体标准编号和年份；适用性应使用机构受控的现行有效法规标准清单、客户合同和项目资料确认。

合规义务类别用于识别外部要求如何转化为软件发行质量要求，不替代行政许可、内容管理、平台准入或其他法定判断。

  • 分组使用限制和法定边界

本分组仅用于 QMS 认证中的技术领域包论证和审核员专业能力控制。管理体系审核不替代政府许可、网络出版管理、游戏作品审批、软件著作权登记、个人信息和数据处理法定评估、网络安全监管、行政执法、平台准入评价或客户行业专门验收。

当项目涉及大型联网游戏、跨区域发行、未成年人保护强相关产品、支付或虚拟资产、关键客户系统软件、云订阅平台、高安全软件或高并发在线服务时，应在项目匹配阶段追加专项确认或技术专家支持。

  • 分组结论与使用口径

QG33-1 可作为质量管理体系软件发行技术领域包使用。机构应记录审核员在电脑游戏发行、其他软件发行、联网游戏、企业软件、云订阅和开源商业发行等分支上的实际能力。组内扩展应以培训、案例评审、专业面谈、见证审核或项目技术支持作为控制手段。
